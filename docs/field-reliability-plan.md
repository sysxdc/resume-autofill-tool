# 字段准确性与组件兼容实施计划

## 第一批：字段核验与写入保护（1.7.0）

- 按字段类型比较，拒绝邮箱、URL、证件号码、GPA 等因通用去标点或包含判断而被误判一致。
- 区分等价显示与精度不足；待核对项不计入已验证填写。
- 最底层普通控件写入默认保护已有值；重试不覆盖用户或异步页面产生的新值。
- 将未写入、待核对和保存未验证分别展示，公开诊断不包含资料原文。
- 补充反例、写入行为回归并运行现有匹配、解析与 DOM 检查。
- 有结构化行 ID 的经历按已有学校/公司/项目名及时间绑定条目，再填子字段；同名歧义、外部记录和重复记录拒绝猜测。
- 范围日期、学校/专业弹窗和年月控件复用结构化绑定；已填写一端的范围控件暂不自动改写另一端。
- GPA 严格解析，移除缺乏依据的百分制线性换算候选。
- iframe 对页面可见的汇报只保留计数、字段键和原因代码。

## 后续批次

1. 经历绑定扩展：当前覆盖具有 `resume*Info_N_field` 结构化行 ID 的记录；无结构化 ID 的记录仍需引入可靠行容器和稳定身份。
2. 组件适配：在现有日期策略与分层模块上统一能力探测、操作、提交、回读协议，优先下拉、级联与日期。
3. 资料结构：兼容旧档案，逐步增加数值单位、日期精度、来源和公司级申请选择。
4. 扩站验证：保留独立样本，真实组件和已安装扩展链路分别验证，公布覆盖率和未支持项。

## 本批验证

- 原单元测试 211 项、新增安全测试 4 组（含邮箱/链接/数值/同名反例）、解析测试 20 项通过。
- DOM 行为用例 34 项通过，覆盖经历倒序、空行分配、重复填写、已有值、异步回填、控件约束、旧节点回读和 iframe 汇报脱敏。
- 真实扩展与组件矩阵 12 项通过：Moka、北森 Phoenix、Ant Design 3/4/5、重新注入、ant-design-vue、Element UI/Plus、Layui 和两组完整 Ant Design 表单。
- 字段匹配既有基准 265/265 通过；该结果只描述基准样本，不代表所有网站的准确率。
- 修复测试工具在 Windows 含空格路径的进程调用与 URL 路径解析；DOM fixture 改用本机 HTTP 服务，避免 file 协议下 fetch 被拦截。生产扩展未新增依赖。

## 当前边界

- 无结构化行 ID 的记录仍有按出现顺序取值的路径；尚不能宣称任意网站的多段经历都已按身份绑定。
- 有一端已填的日期范围暂不自动改写，需要用户补另一端。
- 保存状态默认 `not_checked`；扩展没有自动提交申请或声称服务端已保存。
- 通用组件适配协议、虚拟列表专项、字段来源/精度完整 schema 和公司级申请答案属于后续批次。

## 验收原则

- 错值不能因去标点、子串包含或近似显示而通过严格核验。
- 默认保留用户现有值，重复执行不改变已填内容。
- 日期精度损失、地区信息缺失须待核对，不能视为完全正确。
- 控件回读不能作为服务端已保存的证据。
- 不在真实申请页面执行最终提交；真实资料不进入测试、日志和仓库。
